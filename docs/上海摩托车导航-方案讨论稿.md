# 上海摩托车导航：技术方案讨论稿（非定稿 PRD）

> 2026-09-07 初稿。用于讨论与决策；精确通行边界、数据许可和成本必须经过官方核验/商务确认，不可按本稿直接上线导航。

## 1. 已确认目标与尚未确认的含义

- 首发上海；后端 Rust；Android Kotlin、iOS Swift 原生界面；浏览器测试和 App 测试；路线和导航在无网络时也可用、在线可更新；骑行体验参考 Google Maps 的流畅性、摩途的摩托车专项能力。
- “像 Google Maps 一样丝滑”转为可测指标，而不是承诺其地图覆盖、实时路况或全球能力相同。
- “避开电子眼”有歧义：建议定义为**严格遵守禁限行 + 对经授权且经核验的监控/限速信息做安全提醒**；不把监控点当成允许违法通行的判据，不承诺点位完整、准确或一定免罚。若需求确实是“沿无电子眼道路绕行”，需先明确合规目的、数据权利和安全边界，再决定是否纳入产品。
- “魔途”可能指[摩途](https://www.motumap.com/)；需用户确认。可参考其车牌限行、摩托路线、轨迹/路书等功能，但首期是否做社交/路书需另行确定。

## 2. 最难的前置条件：不是绘制地图，而是取得合法且可离线使用的数据

| 备选路径 | 可做什么 | 无法直接做到什么 | 适用结论 |
|---|---|---|---|
| A：高德/百度标准导航 SDK | 较快实现在线摩托车算路、地图渲染、SDK 离线底图（按权限开通） | 官方开放平台的离线底图 **不等于**无网搜索、摩托车算路、重算路、全程导航；不可以抓取 SDK 数据来建图 | 可作验证体验的短期 PoC，**不满足已提出的完整离线硬要求**；如有专项商业授权需重新评估 |
| B：合法可离线再分发的地图/路网供应商 + 自研 Rust 算路核心 | 离线展示、端侧算路/重算路和可控规则更新 | 采购合同不一定提供路网导出、手机端分发、摩托车路权及可转换许可；研发难度和成本高 | 完整离线硬要求下的首选**条件方案**；先拿样本和合同做 PoC，不签下许可证前不宣称可落地 |

示例候选：[四维图新导航产品](https://lbs.navinfo.com/products/navi.html)称支持离线导航，但其产品宣传不等于允许我方提取路网、供 Android/iOS App 离线存储或二次分发。需要逐项书面确认：上海区域矢量底图/可路由路网、按车牌和车型的路权、POI、手机平台、离线授权、地图审核、可更新权及费用。**不把高德瓦片、搜索或导航结果复制到其他地图体系**：[其服务条款](https://developer.amap.com/pages/terms/)限制存储/缓存与数据混用。OpenStreetMap 仅可用于有条件的研发验证：需验证上海路网覆盖、ODbL 和国内地图合规，不能把其作为无条件生产数据。

## 3. 条件方案 B 的技术路线

```text
合法授权的底图/路网 + 公告/现场复核的摩托车通行规则
                  ↓ 版本化构建流水线（来源、车型/车牌、时段、几何、有效期、审核）
             同一版本的地图包 + 路由图 + 规则包 + 本地检索索引
                  ↓ 签名校验、差分/全量下载、校验后原子切换、失败回滚
Kotlin Android / Swift iOS + MapLibre Native（仅在底图授权允许其渲染时）
                  ↓ UniFFI 调用端侧 Rust 路由/规则核心
Rust 在线服务（Axum 等，路线/包分发/版本管理；PostGIS 管理地理数据）
                  ↔ 浏览器端 MapLibre GL JS 测试页（同 API/同规则夹具）
```

- **Rust 共享核心**：图构建、通行规则匹配、路径搜索、离线重算、路线校验；可用 UniFFI 暴露给 Kotlin/Swift。服务端负责资料审核/发布、增量更新、在线协同，不依赖服务端才可执行核心导航。**定位、地图匹配、连续语音和后台导航**仍须端侧实现与验证；网络断开后不能仅保留一条静态线路。
- 路线硬约束先于时间优化：摩托车车型（普通二轮/轻便等）、号牌、通行区域、方向、道路级别、高架/隧道/桥梁、时段与临时管制；未知规则不能标成“已确认可通行”。对无合法路径或规则过期，应明确告知而非退化为汽车路线。双向道路边界、匝道和转向限制必须建成道路段/转向约束，不能只靠区域多边形。
- 数据每包记录版本、来源、法定生效时间、审核人和过期策略；上线流程包括差异审查与历史回滚。联网可取新版本、交通事件；断网只使用已下载区域与最后一版有效数据，并展示**版本/更新时间及实时封路不可用提示**。上海边界需有缓冲区，否则规划跨市路线无法保证结果。
- 不能默认 MapLibre + 任意第三方地图数据可以混用。地图渲染 SDK、坐标系转换、审图号展示和数据存储/分发方式都须由数据方书面许可与合规审核确认。处理精确行踪信息应按最小必要、授权与本地优先设计。

## 4. 上海首发 MVP（提议，不是已同意范围）

1. 选择摩托车类型/号牌类别，确定起终点和途经点，给出合规优先的路线、里程、预计时间、禁行原因解释；不保证有可达路线。
2. 跟随定位、转弯提示/语音、偏航离线重算、弱 GPS 处理、夜间/手套可操作的大按钮；进入高风险/规则不确定路段前提示。
3. 上海离线包首次联网下载；无网可看图、搜索已下载地点、算路、导航与重算；来网校验并安全更新。跨出数据覆盖区主动提示，不静默规划。
4. 官网/Web 地图**仅作为路线预览与浏览器自动化测试入口**（是否面向用户开放、是否也要全离线，待确认）。
5. 暂缓社交、轨迹分享、全国城市覆盖、实时拥堵预测以及不明来源监控点库；如允许电子眼提醒，只显示授权且标注更新时间的安全警示。

## 5. 验收与测试建议（目标值需真机基线校准）

- **流畅性候选门槛**：主流目标机型导航态目标 60 FPS、帧间隔 p95 ≤ 16.7ms；冷启动至可操作 p95 ≤ 3s；本地上海市内算路/偏航重算 p95 ≤ 2s（均在预定机型、热/冷缓存、固定路线集下测量，未做 PoC 前仅作目标）。另测连续导航发热、电耗、后台恢复、隧道失锁，不能仅以 FPS 判定“丝滑”。
- **规则安全**：对已核验的禁行路段、时段及牌照案例，路线中禁行边命中数为 0；测试“无可达路”、行政边界和法定规则更新前后。现场标志与官方最新通告优先；人工复核多车型/多牌照的上海跨江典型路线。
- **离线闭环**：飞行模式下启动、检索本地点、规划、沿路连续提示、偏航重算均成功；下载中断恢复、包损坏拒绝加载、跨版本一致性及回滚通过。无下载包时不假装可导航。
- **测试矩阵**：Rust 核心性质/单元测试 + 合规路由金标准；Playwright 在浏览器模拟接口、测路线与地图快照；Android UI Automator/仪器测试 + 模拟定位；iOS XCUITest + 模拟定位；真实设备断网/弱网、实地验证。Web 测试不能替代两端 App 与定位硬件测试。

## 6. 合规与验证关卡

[上海公安通行规定](https://www.shanghai.gov.cn/nw12344/20200814/0001-12344_28765.html)涉及不同牌照、车型、区域和路段，含高架及越江限制；[外来机动车规定](https://www.shanghai.gov.cn/nw4338/20200813/0001-4338_247.html)与较新[公安通告](https://gaj.sh.gov.cn/shga/wzXxfbGj/detail?pa=1b89c2c9c1e7a00e4fcbf784730c1c7f7455ef763f297bf2b757918cdd578f0e2a1ce29182a443324dbb851656a139dbf89cd8d0bb43e938)需逐项核对适用次序、有效期和具体边界；不能凭网络摘要生成正式路权。根据[地图管理条例](https://www.gov.cn/zhengce/zhengceku/2015-12/14/content_10403.htm)核对服务主体资质、合法底图/审图、境内数据存储；路网制作与互联网地图服务是否分别需要资质应请法务确认。**当前抓取官方整篇原文受网络环境拦截**，本稿引用官方链接及检索摘录，不是法律意见。

## 7. 请优先确认的 5 个决策

1. “避开电子眼”是否接受定义为**合法路线优先 + 安全提醒**，不以监控空白区优化路线？
2. 首发必须同时 Android+iOS 吗？浏览器是供测试的路线预览，还是另有面向用户的完整导航 Web 版？
3. “离线”是否包含**无网本地检索、算路、偏航重算、全程语音**？本稿按“全部包括”设计。
4. 先服务哪些牌照/车型（沪 A/B、沪 C、外牌；普通二轮/轻便）？是否允许先只做验证过的细分类型？
5. 能否为**正版可离线分发的上海地图+路网**支付商业授权并安排法务审查？若不能，完整离线硬要求下需重新评估可行性和排期。

上述问题确定之后，才把讨论稿升级为正式中文版 PRD：冻结范围、用户故事、数据契约、里程碑、验收和上线门槛。
