# 上海摩托车导航：在线方案讨论稿（第二轮，非正式 PRD）

> 2026-09-07。历史第二轮方案。用户后来明确希望开发后**不支付第三方地图/数据接口费用**；下文“首选高德/备选百度”的商业接口建议已不符合新的成本约束，仅保留为对比，不作为当前定案。首期仍是：不要求离线导航；只做 Android 和功能尽可能一致的浏览器；按已知监控点较少的道路优先；缩放显示电子眼及照片日期；车型选具体摩托车型号。此前的《上海摩托车导航-方案讨论稿.md》也是历史方案，离线和 iOS 部分不再作为当前范围。

## 1. 技术路线变化

- **Rust 后端**负责统一路线接口、摩托车车型配置、牌照规则、摄像头资料/照片审核、候选路线评分、规则版本管理。与持牌地图商的摩托车路线服务对接；服务端持有密钥，前端不直连付费路线服务。首选验证[高德摩托车 Web 服务](https://lbs.amap.com/api/logistic-service/guide/cycling-service/direction-motor)，备选[百度摩托车 WebService](https://lbsyun.baidu.com/docs/webapi?title=directionv2%2Fwebservice-direction%2Fmotorcycle)；都需商业权限、报价与协议核验。**不把汽车/自行车规划冒充摩托车规划。**
- **地图端**：Android 用同一供应商的原生地图 SDK + Kotlin 原生导航 UI；浏览器用其 JavaScript 地图 SDK + TypeScript 导航 UI。Rust 后端向两端返回同一组候选路线、摄像头标注、规则解释；不复用高德 Web 服务结果到未经许可的其他厂商地图上。[高德服务条款](https://developer.amap.com/pages/law-web-service)需法务复核。
- **导航闭环**：两端需要定位、跟随、沿线提示、偏航重算、语音与摄像头图层。网页需要 HTTPS 和定位授权；[W3C 定位规范](https://www.w3.org/TR/geolocation/)对隐藏页面不持续回调：**两端前台功能可对齐，但浏览器息屏/切后台持续导航无法承诺与 Android 一致**。Android 若要锁屏持续导航，应通过原生前台服务实现并验证权限、电耗和后台行为。联网中断要清晰提示路线数据过期/无法重算；可继续显示已加载路线，但不称为离线导航。

## 2. 监控点少的合法路线怎么做

1. 先由持牌服务商生成符合**具体车型、排量及牌照**限行的多条合法候选线路，并对摩托车路权独立核验。上海禁摩规则随牌照、道路、时段变化；车型号无法代替车牌所在地/类型。
2. 对**有授权、来源和有效期**的摄像头点位，按道路方向、覆盖路段、拍摄类型、可能针对摩托车的类别，给候选路线计算“已知点位暴露数”；可设置绕行距离/时间上限。可评估服务商允许的避让多边形功能，但不得让避让点位规则覆盖禁行硬约束；有些目的地不存在已知零点位的合法路线。
3. UI 只称“**已知监控点较少**”，展示预计绕行时间、已知点位数、数据更新日期；不称“无电子眼”或“保证不被拍”。未知点位、移动执法、误差、过期照片都不能证明道路无监控。道路标志与限速仍需遵守。
4. 缩放到设定级别（先试 z≥16，待真机体验测试）展示聚合/去重后的图标，点开显示设备类别、抓拍方向、来源、**现场照片拍摄日期**、上传日期与核验日期。照片拍摄日期仅在具有可靠时间证据时显示；否则明确“拍摄日期未知”，不以公告日期冒充拍摄日期。照片若来自用户投稿，需取得展示许可、模糊车牌/人脸、留审核记录与纠错入口。

目前仅检索到[官方设备设置地点的查询说明](https://gaj.sh.gov.cn/shga/wzXxfbGj/detail?pa=1b89c2c9c1e7a00e4fcbf784730c1c7f705158668007a20059e9fbc3ef498663fa3dff9ed46ea3c2b6446ee45deff24ff89cd8d0bb43e938)和[区级新增设备公告](https://www.shanghai.gov.cn/nw17239/20260107/e808dce2edfb485f8e6ba4f0ede18fef.html)，**尚无已确认可批量使用、可商用再分发、含照片拍摄时间的完整上海摄像头库**。商谈数据商 + 建立投稿审核，均属于上线前置验证项。摩途公开页面提到摩友贡献照片，但[未验证其提供照片拍摄日期](https://apps.apple.com/cn/app/id1187159082)。

## 3. 浏览器与 Android 同功能的边界

| 能力 | 浏览器（前台） | Android 原生 |
|---|---|---|
| 地图/电子眼图层、详情及照片日期 | 支持 | 支持 |
| 车型/车牌、起终点、候选路线、避让偏好 | 共用 Rust API | 共用 Rust API |
| 前台跟随定位、语音、偏航重算 | 开发与真机验证 | 开发与真机验证 |
| 息屏/切后台连续导航 | 无法可靠保证，标明限制 | 可按系统规范开发并验证 |

测试：Rust 路线接口的牌照/限行金标准、无路和点位误报测试；Playwright 浏览器前台端到端；Android UI Automator + GPS 回放；两端相同路线夹具对比；真实设备现场验收和弱网/断网提示。浏览器相同**用户功能**不等于共享原生 UI 实现或能突破平台后台限制。

## 4. 剩余需要用户拍板的问题

1. **牌照**：用户选摩托车型号之外，是否也填写**车牌号或至少号牌类别/归属地**？若不填写，限行规则无法可靠判断，是否允许只查路不开始正式导航？
2. **浏览器的“同功能”**：能接受网页**仅在页面前台**连续导航吗？如果必须网页息屏照常导航，这一要求与标准浏览器能力冲突。
3. **绕行代价**：为减少已知监控点，最多允许多走多远/多久？建议先按“最多比最短合法路线多 20% 时间，且最多 15 分钟”作为**待确认测试值**，并始终给出原合法路线供比较。
4. **照片来源**：是计划采购有商用授权的点位/图片，还是先用官方公告点位 + 摩友自愿上传的现场照片？初始覆盖率、运营审核人力、时间真实性和版权/隐私成本不同。
5. **预算与发布门槛**：能否接受地图商摩托车 API/SDK 的商业授权与点位数据库持续维护成本？若短期找不到可靠照片/时间数据，是否先发布导航和有限的“已核验点位”图层，而不承诺全市完整？

得到这些决定后，再编写正式中文 PRD 和分期验收标准；官方上海交通规则的现行原文、供应商许可及具体点位授权需要上线前逐一核验。
